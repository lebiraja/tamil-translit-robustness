- **Large damage:** vowel drop (V-DROP) and keyboard slips (KEY) roughly double to triple the error (+12 to +15 CER, +128% to +168%). Mixed noise is worst (+15 to +16.5).
- **Small damage:** vowel length (V-LEN), geminate collapse (GEM) and repeated letters (REPEAT) cost only +1 to +2 CER (10% to 21%). DIGRAPH sits between (+3.2 to +3.3).
- **Surprise against the plan:** the plan expected KEY to be mild. It is one of the two most harmful operators. Per edited character it hurts more than V-DROP (KEY changes 7.4% of characters at p=0.3 and costs +12.9 CER for the 1M BiLSTM; V-DROP changes 12.7% and costs +15.0). This is an observation from the manifest and the table, not a controlled test.
- **Monotonic with strength:** for MIX every model degrades monotonically (e.g. BiLSTM 3M: 14.8, 20.4, 25.5, 34.4 CER at 0.1, 0.2, 0.3, 0.5). The other operators were not checked individually here; the full curves are in `results/summary/c1_degradation.csv`.
- **Caveat:** these are synthetic perturbations of formal Wikipedia romanizations, not real chat typing. How well they match real typing is exactly RQ2, which is not answered here.

## 3. RQ4 (C3 under noise): which architecture degrades least?

- Under mixed noise at 0.3 the **Transformer is better at every size** (BiLSTM minus Transformer CER: +0.42 at 1M, +1.30 at 3M, +0.28 at 8M; all CIs exclude zero). Its relative degradation is also smaller (e.g. 3M: +168% against +183%).
- Under clean text the BiLSTM is equal or better (section 1). So there is a trade: the BiLSTM wins slightly on clean text, the Transformer loses less under heavy mixed noise. The gaps are small in absolute terms (0.3 to 1.3 CER) and are the same order as the tuning and seed effects, so I would not state "the Transformer is more robust" as a general result.
- The bootstrap resamples test items and averages seeds; it ignores seed-to-seed variation of the models. With 5 seeds the seed-level comparison has low power. Treat the items-based p-values as describing the test set, not the population of trainings.

Changes against A0 (BiLSTM / Transformer), clean CER, MIX 0.3 CER, AK-all CER:

- A1 random noise: +0.90 / +0.78, −2.32 / −1.78, +2.06 / +1.62
- A2 Tamil-phonological noise: +0.83 / +0.80, −3.03 / −1.81, +1.07 / +1.04
- A3 sampled back-transliteration: −0.33 / −0.51, −0.40 / −0.44, −0.90 / −1.53
- A4 = A2 + A3: +0.35 / −0.03, −3.67 / −2.48, −0.36 / −0.89
- CTRL (fixed romanization of the same words): −0.36 / −0.49, +0.18 / +0.36, −1.00 / −1.51

What the data say:
1. **Noise augmentation (A1, A2) buys robustness but costs clean accuracy.** About +0.8 to +0.9 CER on clean test, more than the 0.5 CER budget set in the plan. Part of this may come from stopping on clean dev CER, which favours the clean model (inference).
2. **A2 against A1:** for the BiLSTM A2 is better on mixed noise (−0.70 CER, CI [−1.00, −0.41]) and much better on vowel drop (17.7 against 21.7), but worse on keyboard noise (23.4 against 18.6), because A2 has no keyboard operator. For the Transformer there is no difference on mixed noise (−0.03, CI [−0.32, +0.27]). The plan's hypothesis that Tamil-aware noise beats random noise holds only for the operators it models.
3. **A3 against its control:** the sampled and the fixed romanizations give the same clean accuracy (BiLSTM +0.03, Transformer −0.02, both CIs include zero). On mixed noise the sampled version is a little better (BiLSTM −0.58, Transformer −0.81 CER, CIs exclude zero). Most of A3's gain over A0 on clean text and on the independent sets is therefore **extra data, not varied spellings** (CTRL gets the same gain). The variety of spellings adds a small robustness gain.
4. **A4 is the best overall:** it removes most of A2's clean cost (BiLSTM +0.35, Transformer −0.03, inside the 0.5 budget) and has the lowest mixed-noise CER (21.8 for both architectures). The extra data in A4 pays for A2's clean loss. The design has no "A2 + CTRL" condition, so we cannot separate how much of A4's noise gain comes from the varied romanizations and how much from the extra data.
5. **Independent sets (AK-all, AK-NEI):** A1 and A2 are worse than A0 (AK-all +1.0 to +2.1). A3, CTRL and A4 are better or equal. The A3 and CTRL words come from the same kind of word list as Aksharantar, so part of that gain may be vocabulary and domain overlap and not robustness (inference; the word pool excludes every independent test word and stem, see `docs/datasets/final-dataset.md`).

### Held-out operators (does robustness transfer?)

- **V-DROP:** A2 trained without V-DROP loses almost all of the vowel-drop benefit (BiLSTM 24.97 against 17.70 for A2, Transformer 22.35 against 17.43). It is even slightly worse than the clean A0 baseline on V-DROP (24.03 and 21.65). Robustness did not transfer to an operator that was left out.
- **GEM:** A2-noGEM is only 0.15 (BiLSTM) and 0.23 (Transformer) CER worse than A2 on GEM, with CIs excluding zero but small. GEM costs only about +1 CER to begin with, so there is little room to show a difference.
- Conclusion: the robustness these augmentations give is operator-specific. A model trained on one error type does not become robust to another.

## 5. Limitations and incidents (read before citing any number)

- **No real typing yet.** All noise here is synthetic and applied to Dakshina romanizations, which are formal Wikipedia text, not chat. The human-typed set and the WhatsApp set are evaluated later on the laptop; RQ2 is open.
- **Tuning used clean dev CER only**, once per architecture and size (seed 100), 20 random trials each. Noisy-condition models inherit the tuned clean hyperparameters. Early stopping uses clean dev CER, which disadvantages noise-trained models.
- **Five seeds** per cell; the statistical power for small differences is low, and the paired bootstrap does not model seed variation.
- **Duplicate-process incident (FIXES F3).** Because of a supervisor bug, 33 of the first 72 finished C2 runs (seeds 0 to 2, finished after 23:56 on 2026-10-21) were trained while one or two duplicate processes trained the same run and shared its checkpoint folder. Checks: (a) a clean re-run of one affected BiLSTM run reproduced the stored result exactly (test CER 10.0306, dev CER 9.2760); (b) a clean re-run of one affected Transformer run differed (test CER 9.30 against 9.13, 32 against 41 epochs), which is expected for a non-deterministic Transformer and is within normal seed variation, so it neither proves nor disproves damage; (c) the evaluator re-scored all 110 stored best checkpoints and compared them with the logged results: only one did not reproduce (`c2-transformer-CTRL-s1`, 8.43 against 8.49). That run was quarantined (`quarantine/`, not deleted) and retrained cleanly; the retrained model reproduces its log exactly (8.899 against 8.899). The other 109 reproduce their logged scores to within 0.05 CER. The decision whether to also retrain the 32 other overlapped runs for stricter provenance is left to the project owner; the checks above suggest it is not needed for the conclusions.
- Other recorded crashes: two CUDA out-of-memory errors in Transformer-8M runs (retried, resumed, completed) and one temp-file collision caused by the duplicate processes (retried). See `logs/failed_runs.txt`.
- Parameter counts are approximate matches (section 1). The reproduction gate (BiLSTM dev CER 8.95, Transformer 9.38, greedy) was passed before these experiments; see `results/gate/`.
